## 几组实际演变

**Agent 8 / Agent 12（pair 4）**：第一轮Agent 8给30；第二轮Agent 12判断对方愿意有限分享，给35；第三轮Agent 12给40；第四轮Agent 8跟随到40。之后双方把40不断称作稳定互惠惯例，第5–21轮都给40。Agent 12第21轮的选择理由强调，高风险厌恶使自己希望保留可靠关系。这是真实的跨轮叙述，但它后来将初始30、35压缩成“始终给40”。

**Agent 10 / Agent 16（pair 7）**：Agent 10前两轮给25；Agent 16在第3轮明确考虑互惠，也给25。第4轮已称作既定互惠惯例，此后到第21轮全部保持25。Agent 10第22轮的`uncertainties`甚至写入“目前继续25”的建议，说明记忆中的不确定性字段会混入行动倾向。

**Agent 4 / Agent 11（pair 10）**：没有锁定单一金额。Agent 4最初给60、50、50，看到搭档给100、90、100后，自己升到65、80，后来回到70–75；Agent 11在90–100间变化。说明模型并非完全不吸收新经历，但这组仍存在上表中的收入方向误读。

## 行为统计及解释限制

只使用第1–21轮的210笔已结算转账：

- 128笔为100，约61.0%。
- 第5–21轮，9/10组组内金额固定：6组100，另外3组分别为90、40、25；只有pair 10持续变化。
- 有非空搭档金额预测的191笔选择中，167笔本人转账金额等于其搭档预测，约87.4%。这表明预期和选择高度匹配，不证明模型机械复制预测金额。
- 第21轮20人的搭档预测信心为17个high、2个medium、1个low。稳定观察后提高信心本身合理，但上面的两例存在明确的错误证据或重复计数。
- 记录中有12次信心上升没有对应新增搭档发送行为；其中一些是模型基于自己的行为形成互惠猜测，不应一概算作事实错误。

合理的风险分担也可能出现稳定合作，不能为了增加差异而强迫Agent改金额。模型仍能看到完整历史，又没有匹配的“同样调用次数但不保留记忆”的对照实验，因此无法据此分离记忆、额外调用、偏好或原模型倾向的影响。

## 第15轮的重复更新

首次调度时，Agent 2未提交转账，其他9位高收入Agent已经提交，所以环境没有结算。下一次调度重新运行全部20人；已提交者的observation从transfer变成waiting，`transfer_submitted`也改变，导致全observation指纹变化。

因此9位已提交者又更新了一次记忆，尽管两次看到的已结算历史都只到第14轮。9次中的预测金额和置信度均未改变，8次文字或引用发生改写。当前证据显示额外开销和不均等的重写机会，不能声称这次重复已造成数值信念漂移。

## 改进顺序

1. **先处理格式容错。** 接受完整、单一JSON代码块的外层包装，保留所有内容校验和原始输出审计；真正非法内容可以进行受预算限制的修正请求。不要替模型补经济选择。
2. **把可计算事实交给程序。** 从本人合法历史生成分开发送者的轮次、金额、机会次数和转账后双方收入。模型负责对事实的主观解释，不承担账目汇总和计数。
3. **明确本次新增事实及判断修正。** 每次更新说明本轮新增了什么、上一轮什么判断被支持或否定；没有新增搭档行为时明确标记，减少错误摘要被直接复制。
4. **避免已完成任务重复调用。** 调度重试只处理本阶段尚未完成者，或使用与新信息/决策阶段绑定的记忆更新标识，而不是任何observation字段变化都触发更新。
5. **后续再评估预期字段是否过于强调匹配。** 数值预期和“对方期待我给多少”可能强化惯例，但应作为独立设计变体检验，不能直接宣称改成区间或增加人格就会更像人。

此前离线测试验证了存储、身份、金额来源和状态边界，不能保证真实模型的自由文字事实可靠。这次应先修已确认的容错和事实呈现问题，再评估私人记忆对经济行为的作用。
